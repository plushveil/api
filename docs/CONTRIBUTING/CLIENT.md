# API

## Client

```ts
import { createClient } from '@plushveil/api/client'
import type { Api } from './api.types.ts'

const client = createClient<Api>({ baseUrl: 'https://api.example.com' })
```

The client is type-safe against whatever `api.types.ts` describes. It does not care whether
that file came from your own `api/` folder or from a third party's `openapi.json` — both CLIs
emit the same shape. See [CLI.md](./CLI.md).

It is built on the global `fetch` and has no dependencies. Nothing about it is generated: one
generated types file plus one generic function.

## `api.types.ts`

Generated, never edited. It exports an `Api` interface keyed by path, then method, plus every
shared schema as a named type.

```ts
// api.types.ts
// Generated by @plushveil/api. Do not edit.

/** A failed request. */
export interface ApiError {
  code: string
  message: string
}

/** A registered user. */
export interface User {
  /** @format date-time */
  createdAt: string
  /** @format email */
  email: string
  /** @format uuid */
  id: string
  name: string
  role: 'admin' | 'member'
}

export interface Api {
  '/users/{userId}': {
    /**
     * Fetch a single user by id.
     * @operationId getUser
     */
    get: {
      path: {
        /** @format uuid */
        userId: string
      }
      query: { include?: 'orders' | 'profile' }
      headers: { 'x-request-id'?: string }
      responses: {
        200: User
        404: ApiError
      }
    }
  }
}
```

Each operation entry is the same shape as the `Operation` interface in a route module, which is
what makes the two directions symmetrical — see [API_FOLDER.md](./API_FOLDER.md). JSDoc tags
are carried through so a reader of the types sees the same constraints the spec declares, and
declarations and properties are in the canonical order from
[Ordering](./TYPE_MAPPING.md#ordering).

A key is **absent** rather than `never` when an operation does not use it — this operation has
no `body`, so there is no `body` key at all. That is what lets the client tell "no request body"
from "a request body typed `never`", and it is what makes the second argument optional for
operations that need nothing.

## Making Requests

One method per HTTP verb: `get`, `post`, `put`, `patch`, `delete`, `head`, `options`.

There is deliberately no `trace` method, even though `trace.ts` is a valid route file: `TRACE`
is a forbidden method in the Fetch standard, so a client built on `fetch` cannot issue one.

```ts
const result = await client.get('/users/{userId}', {
  path: { userId: '3f2a9c1e-0000-4a7b-8c11-b6d2e4f50a91' },
  query: { include: 'profile' },
})
```

The path argument is autocompleted from `Api`, and only paths that declare the verb are
accepted. The second argument's shape follows from the operation: `path` is required when the
path has parameters, `body` is required when the operation declares one, and an operation with
neither takes no second argument at all.

```ts
await client.post('/users', {
  body: { email: 'ada@example.com', name: 'Ada' },
})

await client.get('/health')
```

Path parameters are interpolated and percent-encoded. Query parameters are serialised per the
operation's `style` and `explode` (see [TYPE_MAPPING.md](./TYPE_MAPPING.md)), defaulting to
`form` with `explode: true`; `undefined` values are omitted.

### Per-request options

| Option    | Type                                               | Description                                                                                                                             |
| --------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `path`    | from the operation                                 | Path parameters.                                                                                                                        |
| `query`   | from the operation                                 | Query parameters.                                                                                                                       |
| `headers` | from the operation, plus any string                | Merged over the client's headers.                                                                                                       |
| `cookies` | from the operation                                 | Cookie parameters, serialised into `cookie`.                                                                                            |
| `body`    | from the operation, unwrapped from `Content<M, T>` | Serialised per the operation's media type. A `Uint8Array`/`ArrayBuffer`/`ReadableStream<Uint8Array>` body also accepts a `Blob`/`File`. |
| `signal`  | `AbortSignal`                                      | Cancellation.                                                                                                                           |
| `timeout` | `number`                                           | Overrides the client timeout for this request.                                                                                          |
| `fetch`   | `typeof fetch`                                     | Overrides the implementation for this request.                                                                                          |

A key is required only when the operation declares it and it has required members; an operation
that declares none of `path`, `query`, `cookies`, or `body` takes no second argument at all.

## Results

A result is a union discriminated on `status`, so narrowing gives you the right body type:

```ts
const result = await client.get('/users/{userId}', { path: { userId } })

if (result.status === 200) {
  result.body.email // string
} else if (result.status === 404) {
  result.body.code // string
}
```

| Member     | Type                                               | Description                                                                                        |
| ---------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `status`   | a declared status                                  | A union of the operation's declared status literals, not `number`.                                 |
| `body`     | from the operation, unwrapped from `Content<M, T>` | Parsed per the response content type: JSON, `text/*` as a string, anything else as a `Uint8Array`. |
| `headers`  | `Headers`                                          | Response headers.                                                                                  |
| `response` | `Response`                                         | The underlying response, unread.                                                                   |
| `ok`       | `boolean`                                          | `true` for 2xx.                                                                                    |

`status` is a union of exactly the declared literals, so `switch` over it is exhaustive and a
typo like `result.status === 201` on an operation that never returns `201` is a type error.

An undeclared status at runtime does not widen that type. Narrowing on every declared status
therefore leaves no residual arm, and an undeclared status falls through every branch: the
result still carries the real `status` and the parsed `body`, and a `warn` goes to the console.
Reach it by inspecting `result.response` rather than by narrowing. This keeps the common case
exhaustively checkable, at the cost of making the rare case explicit.

### `throwOnError`

For call sites where only the success path is interesting:

```ts
const client = createClient<Api>({ baseUrl, throwOnError: true })

const user = await client.get('/users/{userId}', { path: { userId } })
user.email // no narrowing needed
```

Non-2xx responses throw `ApiResponseError`, and the return type collapses to the union of
success bodies. This is a client-wide setting; it changes the return type, so it cannot be set
per request.

## Middleware

Client middleware wraps the request:

```ts
client.use(async (request, next) => {
  request.headers.set('authorization', `Bearer ${await token()}`)
  const response = await next(request)
  if (response.status === 401) {
    await refresh()
    return next(request)
  }
  return response
})
```

`request` is a standard `Request` and `next` returns a standard `Response`. Middleware runs in
registration order, outermost first, and may retry by calling `next` more than once.

## Options

| Option            | Type                                                       | Default        | Description                                                                                                                                                                                                                                                                                                           |
| ----------------- | ---------------------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseUrl`         | `string`                                                   | required       | Prepended to every path. A trailing slash is normalised away.                                                                                                                                                                                                                                                         |
| `headers`         | `HeadersInit \| () => HeadersInit \| Promise<HeadersInit>` | `{}`           | Default headers. A function is called per request, for tokens that expire.                                                                                                                                                                                                                                            |
| `fetch`           | `typeof fetch`                                             | global `fetch` | The implementation to use.                                                                                                                                                                                                                                                                                            |
| `middleware`      | `ClientMiddleware[]`                                       | `[]`           | Registered before any `use` call.                                                                                                                                                                                                                                                                                     |
| `timeout`         | `number`                                                   | —              | Milliseconds before the request aborts.                                                                                                                                                                                                                                                                               |
| `throwOnError`    | `boolean`                                                  | `false`        | See above.                                                                                                                                                                                                                                                                                                            |
| `querySerializer` | `(query) => string`                                        | built-in       | Replaces query serialisation entirely.                                                                                                                                                                                                                                                                                |
| `bodySerializer`  | `(body) => { body: BodyInit; contentType?: string }`       | built-in       | Replaces body serialisation entirely. The built-in passes `Uint8Array`, `ArrayBuffer`, `ReadableStream`, `Blob`, `FormData`, and `URLSearchParams` through untouched, defaulting `content-type` to `application/octet-stream` for the first three (the other three already carry their own); everything else is JSON. |

## Errors

| Class              | Thrown when                                                    | Members                                 |
| ------------------ | -------------------------------------------------------------- | --------------------------------------- |
| `ApiResponseError` | A non-2xx response with `throwOnError`.                        | `status`, `body`, `headers`, `response` |
| `ApiRequestError`  | The request never completed — network failure, abort, timeout. | `cause`                                 |

Both extend `Error`. A validation failure from the server is an `ApiResponseError` with status
`400`, whose `body.problems` is the list described in [SERVER.md](./SERVER.md).

## Typing Against Your Own Server

When you own both sides, generate the types from your `api/` folder rather than round-tripping
through a spec:

```bash
api-port ./api --out ./openapi.json --types ./api.types.ts
```

The client then fails to compile the moment a route module's contract changes, which is the
point.
